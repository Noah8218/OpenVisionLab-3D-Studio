# OpenVisionLab 3D Remove Outlier Pixels

Date: 2026-07-28

Status: Complete for the documented software-preparation scope

Backlog item: `D-04`

## Completed scope

OpenVisionLab 3D Studio now owns a typed, deterministic
`Remove Outlier Pixels` preparation step. It removes isolated finite
raw-height samples without mutating the identified source.

The exact rule is:

```text
rule = LocalMedianAbsoluteDeviation
center sample = excluded from the neighborhood
comparison = abs(center - finite-neighbor median) > threshold
window = odd square, 3 / 5 / 7
minimum valid neighbors = explicit
missing input = PreserveMask
boundary = AvailableNeighbors
detected outlier = SetMissing
```

Equality with the threshold is retained. A sample with too few valid
neighbors is retained. Invalid parameters fail closed.

## Ownership

| Layer | Owner |
| --- | --- |
| Packed coordinate-true outlier mask | `C3DOutlierCellMap` in Data |
| Deterministic rule and typed result | `C3DRemoveOutlierPixelsRule` in Tools |
| Recipe validation and adapter | Core validator and Tools recipe execution |
| Preview, Publish, stale state, PropertyGrid, artifact evidence | Workbench ViewModel |
| Derived C3D rendering and compare candidate | Viewer display coordinator and Output Compare |
| Headless replay and JSON report | Runner |

The outlier mask is distinct from the source invalid-cell map. It is immutable,
dimension-sensitive, row-major, and LSB-first, with
`index = row * width + column`. A set bit means that the rule removed the
corresponding valid source sample.

## Operator workflow

1. Add `Remove Outlier Pixels` from Prepare.
2. Edit the typed rule, window, threshold, and minimum-neighbor parameters.
3. Apply the parameter draft. This only updates the recipe and marks prior
   output stale.
4. Select Preview. The Workbench shows before/after valid and missing counts,
   removed count, mask SHA-256, source-unchanged evidence, and the exact
   derived C3D.
5. Select Publish to accept the existing Preview without executing it again.
6. Use Show, Pin, or Compare for the renderable derived C3D.

The Regions surface is hidden for this non-region tool, so unrelated ROI and
`OrientedBox3D` authoring controls do not compete with its parameters and
evidence.

## Boundaries

This is a raw-height software-preparation operation. It does not interpolate
the removed cells, fill holes, certify physical units, or establish metrology.
The Viewer displays the exact derived C3D and the Workbench exposes the
coordinate-true mask identity and before/after counts; a separate colored
per-cell outlier overlay is not claimed.
